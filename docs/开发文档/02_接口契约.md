## 2. 总体说明

| 项 | 约定 |
|---|---|
| Base URL | `http://token-route:9302`（内网） |
| 响应信封 | 6 字段 `ApiResponse`：`code` / `message` / `data` / `error` / `trace_id` / `timestamp`；业务异常 HTTP 200 + 业务码 |
| 字段命名 | 全局 snake_case；ID 一律 String |
| 幂等 | resolve **无需幂等键但不幂等**（重复调用各自预占 lease，超时重试短暂虚占 2 个并发位、靠 lease_ttl 兜底回收）；report 聚合计数**不幂等不去重**（增量观测；10700 后只补发 rejected）；detach 幂等 |
| 鉴权失败语义 | 按模式（§3）：`apikey` 不符 → **HTTP 401**；`jwt` 失败 → **HTTP 200 + code 10200**；`none` 无鉴权 |
| 通用 Header | `X-Trace-Id`（透传或服务端生成，响应头回写） |

## 3. 鉴权模型（内网三模式，无凭证签发/轮换）

token-route 为内网微服务（2 实例，仅族内消费方）——**不做凭证生命周期管理**。各面独立一个服务级配置项三选一，切换 = 改配置滚动重启：

| 模式 | 语义 | 失败语义 |
|---|---|---|
| `none` | 内网信任，零鉴权头（网络隔离即边界） | — |
| `apikey` | 静态共享密钥：请求头 `X-Api-Key` 比对 `tr.auth.api-key`（env 注入；单 key，轮换 = 双端改配置滚动重启） | 不符 → HTTP 401 |
| `jwt` | fwk4j-accesstoken 校验 `Authorization: Bearer <JWT>`；token 由**平台统一认证签发**，token-route 只验不签 | 失败 → 200 + 10200 |

| 配置 | 默认 | 说明 |
|---|---|---|
| `tr.auth.contract-mode` | `none` | 契约面（`/v1/resolve` `/v1/report` `/v1/affinity/**` `/v1/refresh/**`）；jwt 模式 policy `tr-client` |
| `tr.auth.ops-mode` | `jwt` | 运维只读面（`/v1/ops/**`）；jwt 模式 policy `tr-admin`；生产建议保持 jwt |

### 3.1 调用方归因

- 所有契约面请求支持可选头 `X-Caller-Id: <调用方服务名>`——**不校验、仅落决议日志**，供 `[TR-RESOLVE]` 归因排障；
- 无 per-消费方密钥 → 无作用域概念；跨租户拦截不存在（内网信任 + table_id 分配约定，01 §3.2③）。

### 3.2 refresh 鉴权

`POST /v1/refresh/{tid}` **跟随契约面模式**（none 直调 / apikey 带 `X-Api-Key` / jwt 带 token）。

## 5. 资源建模

| 资源 | 标识 | 说明 |
|---|---|---|
| 路由表 route-table | `table_id`（config `tr.tables[].name`） | 一张路由域；表级策略/亲和/租约/FEED 参数——**config 声明，非 API 资源** |
| 路由条目 entry | `entry_id` = `e-{hash(table_id, name)}`（**确定性生成**，服务端推导，上游无需感知） | 表内上游条目；`name` 为 FEED upsert 外部键——确定性 ID 使 upsert 可按 name 直接寻址（status 保留现值的前提），Redis 丢失重建后 ID 稳定；唯一 API 可变来源 = FEED 拉取 |
| 并发租约 lease | `lease_id`（UUID） | resolve 预占凭证；report 释放；超时惰性回收 |
| 亲和绑定 affinity | `tr:affinity:{tid}:{session}` | 非 REST 资源，经 resolve 自动建立 / detach 解除（**无手动 pin**） |

## 6. 契约面接口（运行时）

### TR-CTR-001 取路由 resolve（并发预占）

- **URL**：`POST /v1/resolve`（契约面鉴权模式，§3）
- **用途**：按路由表 + 会话 + 业务参数决议选中条目，并**预占一个并发位**（返回 lease_id）
- **幂等**：读操作；副作用 = 新租约 / 新亲和绑定

请求 Body：

| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| table_id | string | 是 | config 已注册（未注册 → 10400；注册但 OFFLINE → EMPTY + `TABLE_OFFLINE`） | 路由表 |
| session_id | string | 否 | ≤128 字符 | 亲和键；表未开亲和时忽略 |
| biz_params | object | 否 | ≤64 键，值 string/number | 供 filter_script / selector_script 使用 |

```json
{ "table_id": "llm-supply", "session_id": "task-abc-1", "biz_params": { "model": "gpt-4o", "price": "0.02" } }
```

响应 `data`：

| 字段 | 类型 | 说明 |
|---|---|---|
| entry_id | string \| null | 选中条目；空结果为 null |
| data_json | object | 条目业务载荷原样返回（**capacity 约定字段进内核，其余不透明**） |
| lease_id | string \| null | **并发预占凭证**——调用真实上游后必须随 report 回传；EMPTY 时为 null |
| affinity | string | `HIT`（亲和命中）/ `NEW`（新建绑定）/ `NONE`（无亲和或未传 session） |
| reasons | array | 空结果原因码：`ALL_FILTERED` / `TABLE_EMPTY` / `TABLE_OFFLINE` / `CAPACITY_EXHAUSTED` / `SCRIPT_DEGRADED` |

```json
{ "entry_id": "e-1", "data_json": { "base_url": "https://up-a.example.com", "capacity": { "max_concurrency": 20 } }, "lease_id": "3f2a…", "affinity": "NEW", "reasons": [] }
```

**EMPTY 语义**：全部条目被过滤/满载/空表 → `entry_id=null`、`lease_id=null`、HTTP 200 code 0 + reasons，**不抛错不阻塞**。

**预占纪律**：lease_id 生命周期 = 一次真实上游调用；不回传 report → 租约超时（表级 `lease_ttl_seconds`，默认 30s）惰性回收：释放并发、**速率照计（保守）**、健康窗不补计。

### TR-CTR-002 结果回填 report（三态）

- **URL**：`POST /v1/report`（契约面鉴权模式，§3）
- **用途**：消费方回填真实调用结果，驱动服务端集中状态机 + 容量记账（01 §5.2/§5.3）
- **幂等**：聚合计数不幂等不去重（增量观测）

请求 Body：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| reports | array | 是 | 1~100 条，越界 10100 |
| reports[].entry_id | string | 是 | 条目须存在（未知 entry_id 进 rejected） |
| reports[].lease_id | string | 是 | resolve 返回的预占凭证；精确释放并发 |
| reports[].result | string | 是 | `SUCCESS` / `RETRYABLE_FAIL` / `DISABLE_FAIL` |
| reports[].rate_units | number | 否 | 默认 1；速率记账量——`REQUEST` 桶恒按次；`TOKEN`/`BIT` 桶传实际 token 数 / bit 值 |
| reports[].latency_ms | int | 否 | 供观测 |
| reports[].session_id | string | 否 | `DISABLE_FAIL` 时**即时脱离该会话**绑定（其余会话惰性，01 §4.2）；其余 result 仅作日志归因 |

```json
{ "reports": [ { "entry_id": "e-1", "lease_id": "3f2a…", "result": "RETRYABLE_FAIL", "rate_units": 1, "session_id": "task-abc-1" } ] }
```

**三态语义**：

| result | 记账 | 状态机 |
|---|---|---|
| SUCCESS | 释放租约 + 速率记账（窗口累加 rate_units） | 连败清零 |
| RETRYABLE_FAIL | 释放租约 + 速率记账（失败也耗上游资源） | 连败 +1（≥阈值 → FROZEN 即判，退避 5min×4ⁿ 封顶 2h） |
| DISABLE_FAIL | 释放租约 + 速率记账（**调用前拒绝传 `rate_units=0`**） | **立即 FROZEN**（收到即执行的管理动作；本会话亲和即时脱离） |

响应：全部受理 → code 0 `{accepted: N, rejected: []}`；存在拒收（未知 entry_id / 非法 lease）→ **10700**，`data.rejected[]` 携带 `{index, code, message}`。

> **补发纪律**：10700 后**只补发 rejected 条目**——整批重发会使 accepted 部分 win/fail 双计数，污染状态机判定。**迟到 report**（lease 已超时回收，>lease_ttl）按非法 lease 拒收，无需补偿——回收时速率已照计（保守向）。

### TR-CTR-003 亲和解除 detach（消费方）

- **URL**：`POST /v1/affinity/detach`（契约面鉴权模式，§3）
- **用途**：消费方会话终态清理
- **幂等**：是（无绑定返回成功 `{detached:false}`）

请求 Body：`{ "table_id": "llm-supply", "session_id": "task-abc-1" }`

> `table_id` 必填——亲和键空间按表分片（`tr:affinity:{tid}:{session}`），单会话解除不允许跨表 SCAN。

响应：`{ "detached": true | false }`

### TR-CTR-004 立即刷新 refresh

- **URL**：`POST /v1/refresh/{tid}`（跟随契约面鉴权模式，§3.2）
- **用途**：立即拉取 refresh_url 并生效（上游数据变更后 ping）
- **约束**：表必须配置 refresh_url（全 FEED 模式下即所有表）；未注册 table_id → 10400

响应：`{ "pulled": 12, "upserted": 3, "removed": 0, "elapsed_ms": 210 }`
拉取失败 → 200 + code 0 但 `pulled=0` + `error` 字段携带原因（**失败保旧值**，不抛错）。

## 8. FEED 拉取数据契约（refresh_url 上游须实现）

上游暴露 **GET** 端点，返回 JSON：

```json
{
  "entries": [
    { "name": "channel-a", "weight": 100.0, "order_no": 1, "status": "ACTIVE",
      "data_json": {
        "base_url": "https://up-a.example.com",
        "capacity": { "max_concurrency": 20, "rate_limit_value": 5000, "rate_window_ms": 1000, "rate_unit": "TOKEN" }
      } },
    { "name": "channel-b", "weight": 50, "order_no": 2, "data_json": { } }
  ]
}
```

| 规则 | 说明 |
|---|---|
| 全量对比 | 本次返回集 = 该表全量：集内按 `name` upsert；Redis 有而返回集无的条目**移除**（其亲和绑定触发脱离） |
| 字段默认 | weight=100 / order_no 追加序 |
| weight | **允许 float / 负数**（V2.0 放开）——负数 + 权重优先策略 = 价格优先变形（有效权重 = weight × 降级系数）；**负数仅对 WEIGHT_FIRST / SCRIPT 有意义**——WEIGHTED_RANDOM 表按 0 处理（出局） |
| status | 仅接受 `ACTIVE`/`OFFLINE`（管理位）；**缺省 = 保留现值**（不重置状态机判定态 DEGRADED_*/FROZEN）；**显式 ACTIVE = 管理位解冻/上线**（替代原管理面操作） |
| data_json | 业务载荷原样存储/返回，**序列化后 ≤ 8KB**（超限本次拉取整体拒收 10633）；**`capacity` 约定字段进内核**（§8.1），其余不透明；`entry_id` 服务端按 hash(table_id, name) 确定性生成（上游无需感知，决议日志/脚本上下文可见） |
| 失败语义 | 非 200 / 超时（3s）/ schema 非法（10633）→ **保旧值** + 连续失败告警（阈值 3 次） |
| 幂等 | 上游端点须幂等可重入（token-route 惰性触发会周期拉取） |

### 8.1 capacity 约定字段（内核唯一读取的载荷字段）

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `max_concurrency` | int | 不限 | 并发上限；resolve 预占超限 → 条目出局（过滤） |
| `rate_limit_value` | number | 不限 | 窗口内限速量 |
| `rate_window_ms` | long | 1000 | 限速窗口 |
| `rate_unit` | string | `REQUEST` | `REQUEST` / `TOKEN` / `BIT`——report `rate_units` 计量口径 |

> capacity 整体缺省 = 不启用容量治理，条目仅受健康状态机约束。

## 9. 版本与兼容

- URL 版本段**冻结为 `/v1`**（不提供多版本并存；内网微服务，消费方 = 族内薄 SDK）；**破坏性变更 = 契约评审 + SDK 同步升版**；
- 响应只加不减：新增字段向前兼容（SDK `@JsonIgnoreProperties`）；
- resolve 返回 `entry_id`/`data_json`/`lease_id` 为核心三元组，契约冻结优先级最高。
