# token-route 数据设计（Redis 键空间）

> 无实体表（01 §3.2⑥）：本文档即 DBD 等价物——键字典、序列化、Lua 原子操作、TTL 矩阵、容量估算。
> **V2.0**：表壳 config 种子化（进程内存，无 Redis 键）；删除 `tr:tbl` / `tr:strategy` / `tr:ver` / 快照体系；新增容量记账键（租约 + 双速率桶）。
> **V2.1 评审收口**：entry_id **确定性生成**（`e-{hash(tid,name)}`，零映射键）；report 三态统一全记账；L1 并发绑定败者采用胜者；冷启动回源触发条件钉死；亲和脱离统一惰性语义。
> 键前缀 `tr` 为路由域前缀（`tr.key-prefix` 可配）。

## 1. 基础信息

| 项 | 内容 |
|---|---|
| 存储面 | Redis only（fwk4j MultiRedis，datasource `main`） |
| 持久化 | AOF everysec（副本语义强化，不作记账依赖——真源铁律见 01 §4.1：表壳=config、FEED 条目=上游） |
| 拓扑 | **不支持 Redis Cluster**（L1/L3 多键跨槽）；仅主从/哨兵单实例（§5 容量估算亦无分片需求） |
| 时钟源 | 窗口 score / lease deadline 用**应用时钟**（宿主机 NTP 对时，容忍多实例百 ms 级偏差；Lua 内不取 Redis TIME） |
| 序列化 | 值内 JSON 统一 Jackson compact（`fun.commons.tokenroute` 内部 DTO，snake_case） |
| 大键防线 | 单值 ≤10KB（data_json ≤8KB，FEED schema 校验拒绝 10633）；集合均有窗口/上限裁剪（§4） |

## 2. 键空间字典

### 2.1 条目数据面（真源 = 上游 FEED，Redis 为回源缓存）

| 键 | 类型 | TTL | 字段 / 值 | 说明 |
|---|---|---|---|---|
| `tr:entry-ids:{tid}` | SET | 无 | entry_id 集 | 表下条目集合；FEED 全量对比的差集基准（缺失即移除）；**键不存在 = 冷启动信号**（触发单飞同步回源）；键存在但空集 = 上游真空（走 TABLE_EMPTY 不回源——防真空表每请求打上游） |
| `tr:entry:{tid}:{eid}` | STRING | 无 | EntryJSON | `{entry_id, name, weight(float), order_no, data_json(含 capacity), status, frozen_until}`；**entry_id = `e-{hash(tid,name)}` 确定性生成**——按 name 可直接寻址 upsert（status 保留现值的前提），无需 name→eid 映射键；FEED 按 name upsert；resolve 单条 GET / MGET |
| `tr:feed:{tid}` | HASH | 无 | last_pull / fail_count | 拉取游标：惰性触发判断 + 连续失败计数（≥3 告警） |

### 2.2 容量记账面（V2.0 新增）

| 键 | 类型 | TTL | 字段 / 值 | 说明 |
|---|---|---|---|---|
| `tr:conc:{eid}` | ZSET | 惰性回收 | member=`lease_id`，score=deadline（now + lease_ttl） | 并发租约：resolve 预占 ZADD / report 精确 ZREM / 超时 ZREMRANGEBYSCORE 回收；ZCARD 即当前并发 |
| `tr:rate:{eid}:req` | ZSET | 窗口滚动 | member=`{seq}`，score=epochMs | 请求桶：窗口计数 vs `capacity.rate_limit_value` |
| `tr:rate:{eid}:unit` | ZSET | 窗口滚动 | 同上 | 单位桶（TOKEN/BIT）：member=`{seq}:{units}`，窗口求和 vs 限速量；`rate_unit=REQUEST` 时该键不写 |
| `tr:seq:{eid}` | STRING | 无 | INCR | 桶成员唯一序号 |

### 2.3 运行时状态面

| 键 | 类型 | TTL | 字段 / 值 | 说明 |
|---|---|---|---|---|
| `tr:affinity:{tid}:{session}` | STRING | 8h（表级可配，滑动续期） | `{"entry_id":"e-1"}` | 亲和绑定（V2.0 无 pinned 位——手动 pin 已删）；条目态域/容量出域即重绑 |
| `tr:win:{eid}` | ZSET | 滚动清理（>90s 成员惰性剔除） | member=`{seq}:{ok\|fail}`，score=epochMs | 1m 滑动窗调用观测；失败率 = Lua 窗内计数比 |
| `tr:fail:{eid}` | STRING | 无 | 连败计数 | SUCCESS 报告 DEL 清零；≥阈值（default 5）即判冻结（channel-legacy 预设已降 P2，V1 单预设） |
| `tr:rr:{tid}` | STRING | 无 | INCR 整数 | ROUND_ROBIN 轮询游标（多实例一致），对条目 ID 集取模 |
| `tr:log:resolve:{tid}` | LIST | 7d | 单行 JSON，LPTRIM 1000 | 决议日志热窗（ops 查询读此；全量走 `[TR-RESOLVE]` → Loki） |
| `tr:log:aff:{tid}` | LIST | 7d | `{type:BIND\|DETACH, session, entry_id, at, by}` | 亲和事件 |
| `tr:log:state:{eid}` | LIST | 7d | `{from, to, reason, at, by}` | 状态迁移史（by = STATE_MACHINE / REPORT_DISABLE / FEED_STATUS） |
| `tr:sched:lock:v1:{job}` | — | lease | Redisson | 评估器/拉取单飞多实例锁（tryLock waitTime=0） |

> **已删除键（V2.0）**：`tr:tbl:{tid}`（表壳=config 内存）/ `tr:strategy:{sid}`（策略=脚本文件）/ `tr:ver:{tid}`（无 SDK 缓存锚）/ 快照导出目录。

## 3. Lua 原子操作清单（多键一致性边界）

运行时热路径全部 Lua 单往返；配置面写已随管理面删除（FEED 拉取为唯一条目写方）：

| # | 脚本 | 键 | 原子语义 |
|---|---|---|---|
| L1 | `resolve_bind` | affinity / entry / conc / seq / log:aff | 亲和 MISS 分支：绑定 SET NX+TTL + **并发预占**（容量校验：ZCARD conc < max 且桶有余 → ZADD lease）+ log push；同 session 并发 resolve 仅一个 NEW——**败者采用胜者绑定**（等价 HIT 返回，不重跑策略） |
| L2 | `affinity_hit` | affinity / entry / conc / rate | GET 绑定 → 条目态域校验 {ACTIVE,L1} + **容量校验**（并发/速率有余）→ TTL 续期 + 预占；任一出域 → 返回 MISS 触发重绑 |
| L3 | `report_aggregate` | conc / rate / seq / win / fail / entry / log:state / log:aff | report 核心：ZREM conc（精确释放）→ **速率记账**（ZADD req +unit，**三态全记**，`rate_units=0` = 调用前拒绝）→ 三态分支（SUCCESS: DEL fail + win ok；RETRYABLE_FAIL: INCR fail + win fail，**≥阈值即判 FROZEN** + frozen_until 计算 + 迁移日志；DISABLE_FAIL: 直写 FROZEN + 迁移日志 + **本会话即时脱离 DEL**（session_id 入参），其余会话惰性）|
| L4 | `evaluate_transition` | entry / win / log:state | 评估器逐条目：窗清理（ZREMRANGEBYSCORE）→ 计数 → 爬升（L1→L2→L3）/ 一步恢复 / 惰性解冻（frozen_until < now → ACTIVE）；CAS 式迁移（脚本内比对当前 status） |
| L5 | `entry_upsert` | entry-ids / entry / log:aff | FEED 全量对比（确定性 eid 直接寻址，无需 name 索引）：SADD 新增 / SET 更新 / SREM+DEL 移除（移除条目的亲和绑定**惰性脱离**——L2 校验 entry 缺失自然 MISS 重绑，无反向索引不扫描）；status 缺省保留现值、显式 ACTIVE/OFFLINE 为管理位 |
| L6 | `lease_reclaim` | conc / rate | 租约超时回收：ZREMRANGEBYSCORE conc（deadline < now）→ 每回收一个：速率照计（ZADD req/unit）+ 健康窗不补计；resolve/report 路径顺带触发（无独立定时器） |

> 速率桶窗口滚动由 L3/L6 顺带 ZREMRANGEBYSCORE；`tr:seq` INCR 生成成员唯一序号。

## 4. TTL / 裁剪矩阵

| 数据 | TTL / 裁剪 | 策略 |
|---|---|---|
| 亲和绑定 | 8h（表级可配） | 每次 HIT 滑动续期；到期即脱离（下次 resolve 重绑） |
| 并发租约 | lease_ttl（表级默认 30s） | report 精确释放；超时 L6 惰性回收（速率照计保守向） |
| 滑动窗成员 | score > now-90s 惰性清理 | L3/L4 顺带 ZREMRANGEBYSCORE |
| 速率桶成员 | score > now - rate_window 惰性清理 | 同上 |
| ring 日志 | 7d | 键级 EXPIRE + LPTRIM 1000 |
| 条目数据 / entry-ids | 无 TTL | FEED 全量对比维持（真源=上游） |
| 连败计数 | 无 TTL | SUCCESS 即清零 |

## 5. 容量估算（P1 规模假设：10 表 × 200 条目）

| 数据 | 单位开销 | 总量 |
|---|---|---|
| entry-ids + entry | EntryJSON ≈ 0.5KB（data_json ≤8KB 上限） | 2000 条目 ≈ 1~2MB |
| 并发租约 | 100B × 活跃调用（1 万并发估） | ≈ 1MB |
| 速率桶 | 每条目窗内 ≤ 窗口/秒 × 30B | 可忽略 |
| 亲和绑定 | 200B × 活跃会话（1 万会话估） | ≈ 2MB |
| ring 日志 | 10 表 × 3 ring × 1000 行 × 0.3KB | ≈ 9MB |
| **合计** | — | **< 30MB**（单 Redis 实例余量充足，无分片需求） |

## 6. 与 mc-cache 规范对齐自查

| 铁律 | 落实 |
|---|---|
| 必设 TTL / 禁 KEYS | 全键 TTL/裁剪见 §4；无扫描面（detach 必带 table_id，02 §6 TR-CTR-003） |
| 大键 / 热键 | ring LPTRIM 1000；resolve 热路径单键 GET + Lua 单往返，无 KEYS/SCAN |
| 写失败不阻塞业务 | Redis 不可用 → resolve EMPTY（不误动作）、report 10700 部分/全拒，消费方按降级预案（01 §9） |
| 原子性 | 多键语义全 Lua（§3），禁应用层多命令拼装 |
