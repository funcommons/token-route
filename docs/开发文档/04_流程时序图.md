## 1. resolve 决议全链路（含并发预占）

02 §6 TR-CTR-001 —— 三层取数 → 过滤（状态域+容量+参数）→ 亲和 → 策略 → Lua 预占落账。

```mermaid
sequenceDiagram
    autonumber
    participant C as 消费方业务代码<br/>外部
    participant RC as TrResolveController<br/>token-route · 契约面
    participant RS as TrResolveService<br/>token-route · 决议引擎
    participant RD as Redis<br/>(条目+记账+亲和)

    C->>RC: POST /v1/resolve {table_id, session_id?, biz_params?}
    RC->>RC: 鉴权模式校验 (none 直过 / apikey 不符 401 / jwt 失败 10200)
    RC->>RC: 调用方归因 X-Caller-Id (可选头·仅日志)
    RS->>RS: 表壳读取 (进程内存 config 注册表·零 IO)
    alt 条目列表龄 > refresh-interval (惰性触发)
        RS->>RS: 服务旧值继续 + 单飞后台拉取 (图4①)
    end
    RS->>RD: SMEMBERS tr:entry-ids + MGET tr:entry<br/>(键不存在=冷启动→单飞回源·空集=真空走 TABLE_EMPTY·单条 miss 回源一次 3s)
    RS->>RD: 状态读 (entry.status / conc ZCARD / 桶水位)
    RS->>RS: 过滤链 ① 状态域 {ACTIVE, DEGRADED_L1}<br/>② 容量 (并发<max 且速率桶有余) ③ filter_script 谓词
    alt 亲和开启 且 session 非空
        RS->>RD: Lua L2 affinity_hit (态域+容量校验+TTL 续期+预占)
        alt HIT
            RD-->>RS: 绑定条目 + 新 lease_id
        else MISS (无绑定 / 态域出域 / 满载)
            RS->>RS: 策略选择
            RS->>RD: Lua L1 resolve_bind (SET NX + 预占 + 事件日志)<br/>并发同 session 仅一个 NEW
        end
    else 无亲和 / 未传 session
        RS->>RS: 策略选择 (加权随机 / 顺序轮询 rr 游标 / 权重优先 weight×降级系数·允许负数 / 脚本选择器)
        RS->>RD: Lua 并发预占 (ZADD tr:conc member=lease_id score=deadline)
    end
    RS->>RD: ring 决议日志 + [TR-RESOLVE] 单行结构化日志
    RC-->>C: {entry_id, data_json, lease_id, affinity: HIT|NEW|NONE, reasons[]}
    Note over RS: 全过滤/满载/空表/表停用 → entry_id=null + reasons=[ALL_FILTERED|CAPACITY_EXHAUSTED|TABLE_EMPTY|TABLE_OFFLINE]<br/>HTTP 200 code 0 不抛错 (EMPTY 语义)
    Note over C,RS: 消费方持 lease_id 调真实上游 → 结果经 report 回传 (图2)·不回传则租约超时回收
```

## 2. report 三态回填 → 记账 → 冻结判定

02 §6 TR-CTR-002 —— 批量聚合 → 精确释放租约 → 速率记账（三态全记）→ 三态状态机。

```mermaid
sequenceDiagram
    autonumber
    participant C as 消费方业务代码<br/>外部
    participant RB as TrReportBatcher<br/>token-route-sdk · 批量器
    participant RC as TrReportController<br/>token-route · 契约面
    participant RD as Redis<br/>(记账+状态面)

    C->>RB: report(entryId, leaseId, result, rateUnits)
    RB->>RB: 缓冲 (满 100 条或 1s 满窗)
    RB->>RC: POST /v1/report (按鉴权模式·批量 ≤100)
    RC->>RD: Lua L3 report_aggregate (逐条·pipeline 单 socket 批发送)
    RD->>RD: ZREM tr:conc (lease_id 精确释放并发)<br/>速率记账 ZADD req=1 + unit=rate_units (三态全记·rate_units=0=调用前拒绝)
    alt SUCCESS
        RD->>RD: DEL tr:fail (连败清零) + 窗计 ok
    else RETRYABLE_FAIL
        RD->>RD: INCR tr:fail + 窗计 fail (速率照计)
        alt 连败 ≥ 阈值 (即判即升)
            RD->>RD: status → FROZEN<br/>frozen_until = now + 5min×4ⁿ (封顶 2h)<br/>ring 迁移日志
            Note over RD: 绑定该条目的亲和会话:<br/>下次 resolve L2 态校验脱离 → 自动重绑
        else 未达阈值
            RD->>RD: 仅计数 (评估器图3 后续判定爬升)
        end
    else DISABLE_FAIL
        RD->>RD: 直写 status → FROZEN (收到即执行·速率照记)<br/>迁移日志 by=REPORT_DISABLE + 本会话亲和即时脱离 (DEL 该 session 键)
    end
    RC-->>RB: code 0 {accepted, rejected[]} / 部分成功 10700
    Note over RB: 未知 entry_id / 非法 lease 进 rejected·其余照常受理<br/>不幂等不去重 (增量观测)
    RB-->>C: 异步回调 (全异常吞·不入业务主链)
    Note over C,RD: 不回填 → 租约超时 L6 惰性回收:<br/>释放并发 + 速率照计 (保守) + 健康窗不补计 (01 §5.2)
```

## 3. 每分钟评估器（降级爬升 / 恢复 / 惰性解冻）

01 §4.2 —— 爬升/恢复/解冻由定时评估驱动，Redisson 多实例锁防重入。

```mermaid
sequenceDiagram
    autonumber
    participant SCH as SchedulerRunner<br/>token-route · 调度装配
    participant EJ as TrEvaluateJob<br/>token-route · 评估器
    participant RD as Redis<br/>(状态面)

    SCH->>SCH: fixedDelay 60s 触发
    SCH->>RD: tryLock(tr:sched:lock:v1:evaluate, waitTime=0, lease=60s)
    alt 他实例持锁
        SCH-->>SCH: 本轮跳过 (不堆积)
    else 持锁成功
        loop 逐条目 (entry-ids 游标遍历·无 KEYS·含 FROZEN 解冻检查)
            EJ->>RD: Lua L4 evaluate_transition
            RD->>RD: ZREMRANGEBYSCORE 清 90s 外窗成员
            alt 窗内调用 ≥10 且失败率 ≥50%
                RD->>RD: ACTIVE→L1 (权重×0.5) / L1→L2 / L2→L3 (每评估窗爬一级)
            else 窗内调用 ≥10 且失败率 <10% (或无失败)
                RD->>RD: L1/L2/L3 → ACTIVE (一步恢复)
            else FROZEN 且 frozen_until < now
                RD->>RD: 惰性解冻 → ACTIVE
            else 未达阈值
                RD-->>RD: 状态不变
            end
            RD->>RD: 迁移即: ring 日志 + [TR-STATE]
        end
        EJ->>EJ: [TR-STATE] 单行结构化日志 (迁移汇总)
    end
    Note over SCH: finally unlock + isHeldByCurrentThread 守卫<br/>(对齐 thmp-app SchedulerRunnerConfig 模板)
```

## 4. FEED 三触发（惰性 / 立即 / 冷启动回源）

01 §5.5 / 02 §8 —— 纯拉取无 push：条目数据唯一写方。

```mermaid
sequenceDiagram
    autonumber
    participant UP as 上游供给系统<br/>外部 (refresh_url GET)
    participant C as 上游/运维<br/>外部 (ping 责任方·消费方无需调用)
    participant FR as TrFeedRefreshService<br/>token-route · 拉取器
    participant RD as Redis<br/>(条目面)

    rect rgb(235, 244, 255)
    Note over FR,UP: ① 惰性: resolve 命中条目列表龄 > refresh-interval (默认 60s)
    FR->>FR: 服务旧值先返回 + 单飞后台拉取
    FR->>UP: GET refresh_url (超时 3s)
    UP-->>FR: {entries:[...]} 全量
    end

    rect rgb(240, 255, 240)
    Note over C,UP: ② 立即: 上游变更后 ping (TR-CTR-004·责任方=上游/运维)
    C->>FR: POST /v1/refresh/{tid} (跟随契约面鉴权模式)
    FR->>UP: GET refresh_url (同步·3s)
    UP-->>FR: {entries:[...]}
    FR-->>C: {pulled, upserted, removed, elapsed_ms}
    end

    rect rgb(255, 248, 235)
    Note over FR,UP: ③ 冷启动/条目 miss: resolve 读条目未命中 → 同步回源拉一次
    FR->>UP: GET refresh_url (同步 3s·失败按无此条目不阻塞)
    UP-->>FR: {entries:[...]}
    end

    FR->>FR: schema 校验 (02 §8: name 键 / status 值域 / capacity 字段 / 10633)
    alt 拉取/校验失败
        FR->>FR: 保旧值 + 连续失败 ≥3 告警 (tr:feed fail_count)
    else 成功
        FR->>RD: Lua L5 entry_upsert: 按 name 全量对比<br/>新增/更新 upsert · 缺失移除 (其亲和绑定触发脱离)
        Note over RD: status 缺省保留现值 (不重置判定态)<br/>显式 ACTIVE/OFFLINE = 管理位解冻/下线
    end
```

## 5. config 表定义生效链

01 §5.6 —— 零管理写面：表壳与脚本走部署配置，启动 fail-fast，滚动重启生效。

```mermaid
sequenceDiagram
    autonumber
    participant OPS as 运维/开发<br/>外部
    participant CFG as 配置文件<br/>tr.tables + 脚本文件 (.groovy)
    participant APP as token-route 实例<br/>(×2 滚动)
    participant RD as Redis<br/>(条目面)

    OPS->>CFG: 改表定义 / 调亲和参数 / 换脚本 (随部署制品评审·版本化)
    OPS->>APP: 滚动重启 (实例1 → 健康 → 实例2)
    APP->>CFG: 启动加载 tr.tables
    alt 脚本编译失败 / schema 非法 (10630/10633)
        APP-->>APP: 拒绝启动 fail-fast (日志指名表/脚本·坏配置进不了线上)
    else 编译通过
        APP->>APP: selector/filter 脚本编译缓存 + 表注册表进进程内存
        APP->>RD: 首个 resolve 触发 FEED 拉取 (条目回源·图4③)
    end
    Note over APP,RD: 运行期无任何配置写接口 (零管理写面)<br/>上游条目数据变更不走此链 → 改 FEED 数据 + ping (图4②)
```

## 6. Redis 故障自愈

01 §9 —— 表壳在内存不受影响；条目/亲和/计数沉没可自愈或可接受。

```mermaid
sequenceDiagram
    autonumber
    participant C as 消费方业务代码<br/>外部
    participant TR as token-route<br/>(契约面)
    participant RD as Redis<br/>(沉没)
    participant UP as 上游供给系统<br/>(FEED 真源)

    rect rgb(255, 240, 240)
    Note over TR,RD: 故障期: 不误动作
    C->>TR: POST /v1/resolve
    TR-->>C: EMPTY (Redis 不可达·不抛 5xx 不阻塞·reasons 提示)
    Note over TR: report → 10700 拒收·ops 只读面降级<br/>表壳在进程内存·表定义与脚本不受影响
    end

    rect rgb(240, 255, 240)
    Note over TR,UP: 恢复期: 回源自愈
    TR->>RD: Redis 恢复
    TR->>UP: 下一轮惰性/条目 miss 拉取 refresh_url 自愈 (≤60s)
    UP-->>TR: {entries:[...]} → Lua L5 回灌
    Note over RD: 亲和绑定丢失 = 会话重绑新条目 (任务 ID 即天然亲和键·可接受)<br/>租约/计数丢失 = 并发归零短暂放开 + 消费方超时对账收敛
    end
```
