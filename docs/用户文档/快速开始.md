# token-route 快速开始

> 目标：10 分钟内在本机跑通「建表 → 取路由 → 回填结果 → 冻结/解冻」完整闭环，直观感受 **resolve + report 双接口模型**。
> 本页自包含，无需任何预备知识；想理解设计背景再读 [01_消费方接入手册.md](./01_消费方接入手册.md)。

## 1. 环境要求

| 依赖 | 版本 | 用途 |
|---|---|---|
| JDK | 17+ | 运行 token-route |
| Redis | 5+（建议 7.x） | 唯一存储（无 PG/无其他中间件） |
| Docker + Compose | 可选 | 一键起服务（方式一） |
| Python 3 | 可选 | 起一个静态服务器模拟 FEED 上游 |

## 2. 第一步：准备一个模拟上游（FEED 数据源）

token-route 的条目数据来自上游 FEED 端点（一个 GET 接口，返回全量条目）。演示用静态 JSON 即可，零编码：

`demo/entries.json`：

```json
{
  "entries": [
    { "name": "up-a", "weight": 70, "status": "ACTIVE",
      "data_json": { "base_url": "https://up-a.example.com", "api_path": "/v1/task",
                     "capacity": { "max_concurrency": 5, "rate_unit": "REQUEST" } } },
    { "name": "up-b", "weight": 30,
      "data_json": { "base_url": "https://up-b.example.com", "api_path": "/v1/task" } }
  ]
}
```

```bash
cd demo && python3 -m http.server 9500
# 验证：curl http://localhost:9500/entries.json
```

> 注意：`up-a` 带 `"status": "ACTIVE"` 是为了第 6 步演示「显式 ACTIVE 解冻」。

## 3. 第二步：写最小表种子（config）

token-route 零管理写面——建表 = 写一份配置。`demo/application.yml`：

```yaml
tr:
  auth:
    contract-mode: none      # 演示内网信任；生产建议 apikey 或 jwt
    ops-mode: none           # 演示 ops 免鉴权；生产必须 jwt
  tables:
    - name: demo-table                 # 即 table_id
      strategy-type: WEIGHTED_RANDOM   # 加权随机（70/30）
      affinity:
        enabled: true                  # 开亲和：同 session 黏住同条目
      feed:
        refresh-url: http://host.docker.internal:9500/entries.json
        interval-seconds: 60
```

字段全量说明见 [配置手册 §3](./配置手册.md)；本演示只用到以上 7 项。

## 4. 第三步：启动 token-route

**方式一 · Docker Compose**（推荐）：

```yaml
# docker-compose.yml
services:
  redis:
    image: redis:7-alpine
    ports: ["6379:6379"]
  token-route:
    image: funcommons/token-route:latest    # P1 交付后由族内制品库提供
    ports: ["9302:9302"]
    environment:
      TR_REDIS_HOST: redis
    volumes:
      - ./application.yml:/conf/application.yml
    depends_on: [redis]
```

```bash
docker compose up -d
curl http://localhost:9302/actuator/health    # → {"status":"UP"}
```

**方式二 · 本地运行**：

```bash
redis-server &                                  # 或使用已有 Redis
mvn spring-boot:run -Dspring-boot.run.arguments="--spring.config.additional-location=file:./demo/application.yml"
```

## 5. 第四步：三步验证闭环

```bash
BASE=http://localhost:9302

# ① 取路由（带 session_id，亲和生效；返回 lease_id 并发预占）
curl -s -X POST $BASE/v1/resolve -H "Content-Type: application/json" \
  -d '{"table_id":"demo-table","session_id":"demo-session-1"}'
# → entry_id="e-xxxx"（约 70% 概率 up-a）、affinity="NEW"、lease_id="…"

# ② 同 session 再 resolve —— 亲和命中：affinity="HIT" 且与 ① 同一条目
curl -s -X POST $BASE/v1/resolve -H "Content-Type: application/json" \
  -d '{"table_id":"demo-table","session_id":"demo-session-1"}'

# ③ 回填结果（真实场景 = 你调用完上游后回填；演示直接回填 SUCCESS）
curl -s -X POST $BASE/v1/report -H "Content-Type: application/json" \
  -d '{"reports":[{"entry_id":"<①返回的entry_id>","lease_id":"<①返回的lease_id>","result":"SUCCESS","rate_units":1}]}'
# → {"code":0,"data":{"accepted":1,"rejected":[]}}
```

跑通即接入完成——你的服务只需重复这三步（[接入手册 §5](./01_消费方接入手册.md) 有完整任务级走查）。

## 6. 附加演练：冻结 → 解冻（状态机直观感受）

```bash
# ① 用一个新 lease 回填 DISABLE_FAIL（强信号：立即全局冻结）
curl -s -X POST $BASE/v1/resolve -H "Content-Type: application/json" \
  -d '{"table_id":"demo-table","session_id":"demo-session-2"}'
# 拿到 up-a 的 entry/lease 后：
curl -s -X POST $BASE/v1/report -H "Content-Type: application/json" \
  -d '{"reports":[{"entry_id":"<up-a的entry_id>","lease_id":"<对应lease>","result":"DISABLE_FAIL","rate_units":0}]}'

# ② 再 resolve 多次 —— up-a 完全出局，只返回 up-b；新 session 不再命中 up-a
# ③ ops 面观察：status=FROZEN
curl -s $BASE/v1/ops/tables/demo-table/status | python3 -m json.tool

# ④ 解冻（管理位）：给 entries.json 的 up-a 显式保留/补上 "status":"ACTIVE"，ping 立即刷新
curl -X POST $BASE/v1/refresh/demo-table
# ⑤ 再看 ops：status=ACTIVE，重新参与选择
```
