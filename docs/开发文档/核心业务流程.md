
**架构要点**：

| 要点 | 说明 |
|---|---|
| 零管理写面 | 表壳（策略/亲和/refresh_url）与脚本全部来自 config 种子，启动加载；换表 = 改配置 + 滚动重启 |
| 全 FEED | 条目数据唯一写方 = refresh_url 拉取；Redis 只是回源缓存（真源铁律） |
| 表壳在内存 | Redis 沉没不影响表定义与脚本——故障域收窄（01 §9） |
| 双接口模型 | resolve（取条目 + 并发预占，返回 lease_id）+ report（三态回填 + 记账） |
| 边界 | 不代理流量；不做调用方/用户·key 限流（那是网关侧职责）；只做条目（上游）容量治理 |

## 2. 核心流程一：获取路由条目（resolve + 并发预占）

```mermaid
flowchart TD
    A["POST /v1/resolve<br/>table_id + session_id? + biz_params?"] --> B["鉴权模式校验 + X-Caller-Id 归因"]
    B --> C["表壳读取（进程内存 config）"]
    C --> D["三层取数<br/>条目 ID 列表 → 条目数据 → 状态"]
    D --> E["过滤链"]
    E --> E1["① 状态域过滤<br/>ACTIVE / DEGRADED_L1 可选<br/>L2 排水·L3/FROZEN/OFFLINE 出局"]
    E1 --> E2["② 容量过滤<br/>并发占用 < max_concurrency<br/>且速率桶有余"]
    E2 --> E3{"③ filter_script 谓词（可选）"}
    E3 -->|"false / 异常"| OUT["条目出局"]
    E2 -->|"候选为空"| EMPTY["EMPTY：entry_id=null + reasons<br/>ALL_FILTERED / CAPACITY_EXHAUSTED / TABLE_EMPTY / TABLE_OFFLINE"]
    E3 -->|"通过"| F{"亲和开启且 session 非空？"}
    F -->|"是"| G["Lua L2 affinity_hit<br/>绑定存在 + 态域/容量达标 → TTL 续期"]
    G -->|"HIT"| K
    G -->|"MISS（无绑定/出域/满载）"| H
    F -->|"否"| H["策略选择"]
    H --> S1["加权随机：按 weight 抽样"]
    H --> S2["顺序轮询：rr 游标 + order_no"]
    H --> S3["权重优先：有效权重 = weight × 降级系数<br/>weight 允许 float/负数（负数 = 价格优先变形）"]
    H --> S4["脚本选择器：Groovy 代入条目集<br/>返回条目 ID"]
    S1 --> I
    S2 --> I
    S3 --> I
    S4 --> I
    F -->|"否（无亲和）"| H
    I["Lua 原子落账<br/>亲和绑定（SET NX）+ 并发预占（lease ZADD）+ 事件日志"]
    K["Lua 预占（亲和 HIT 分支）"]
    I --> J["ring 决议日志 + TR-RESOLVE 结构化日志"]
    K --> J
    J --> L["返回 entry_id + data_json + lease_id + affinity"]
    EMPTY --> L2["返回 entry_id=null + lease_id=null + reasons（HTTP 200）"]
```

> 预占纪律：lease_id 生命周期 = 一次真实上游调用；不回传 → 租约超时（默认 30s）惰性回收——释放并发、速率照计（保守）、健康窗不补计。

## 3. 核心流程二：更新条目状态（report 三态回填）

```mermaid
flowchart TD
    A["POST /v1/report<br/>entry_id + lease_id + result + rate_units"] --> B["Lua L3 report_aggregate"]
    B --> C["精确释放租约（ZREM conc）<br/>速率记账（req=1 + unit=rate_units·三态全记，0=调用前拒绝）"]
    C --> D{"result？"}
    D -->|"SUCCESS"| E["连败计数清零 + 窗计 ok"]
    D -->|"RETRYABLE_FAIL"| F["连败 +1 + 窗计 fail（速率照计）"]
    F --> G{"连败 ≥ 阈值？"}
    G -->|"是（即判即升）"| H["FROZEN<br/>frozen_until = 5min × 4ⁿ 封顶 2h<br/>亲和绑定触发脱离"]
    G -->|"否"| I["仅计数（评估器后续判定爬升）"]
    D -->|"DISABLE_FAIL"| J["立即 FROZEN（收到即执行）<br/>迁移日志 by=REPORT_DISABLE·本会话即时脱离"]
    E --> K["返回 accepted / 10700 部分成功"]
    H --> K
    I --> K
    J --> K
    C -.->|"不回填（消费方丢失）"| T["租约超时 L6 惰性回收<br/>释放并发 + 速率照计 + 健康窗不补计"]
```

## 4. 条目状态机

```mermaid
stateDiagram-v2
    [*] --> ACTIVE : FEED 首次出现（缺省）
    ACTIVE --> OFFLINE : FEED 显式 status=OFFLINE
    OFFLINE --> ACTIVE : FEED 显式 status=ACTIVE（管理位解冻）
    ACTIVE --> DEGRADED_L1 : 窗(1m) 调用≥10 且失败率≥50%
    DEGRADED_L1 --> DEGRADED_L2 : 持续 1 评估窗仍达标
    DEGRADED_L2 --> DEGRADED_L3 : 持续 1 评估窗仍达标
    DEGRADED_L1 --> ACTIVE : 失败率<10% 一步恢复
    DEGRADED_L2 --> ACTIVE : 失败率<10% 一步恢复
    DEGRADED_L3 --> ACTIVE : 失败率<10% 一步恢复
    ACTIVE --> FROZEN : 连败≥5 / RETRYABLE_FAIL 超限 / DISABLE_FAIL
    DEGRADED_L1 --> FROZEN : 连败≥5 / DISABLE_FAIL
    FROZEN --> ACTIVE : 窗满惰性回（5min×4ⁿ 封顶 2h）/ FEED 显式 ACTIVE
```

| 状态 | 参与选择 | 有效权重 | 亲和 |
|---|---|---|---|
| ACTIVE | ✅ | weight × 1 | ✅ |
| DEGRADED_L1 | ✅ | weight × 0.5 | ✅ |
| DEGRADED_L2 | ❌ 排水（存量会话继续） | — | ✅ 命中续用 |
| DEGRADED_L3 / FROZEN / OFFLINE | ❌ | — | ❌ 脱离重绑 |

> 判定参数化：`default` 预设 = 上图窗口制（**V1 唯一预设**）；`channel-legacy` 预设（连败 ≥3 → ×0.5 / 连败 ≥5 → FROZEN）**P2 交付**（表级 `state_policy`，01 §4.2）。

## 5. 关键时序图

### 5.1 resolve（含预占，精简版）

```mermaid
sequenceDiagram
    autonumber
    participant C as 消费方
    participant TR as token-route
    participant RD as Redis

    C->>TR: POST /v1/resolve {table_id, session_id?, biz_params?}
    TR->>TR: 表壳(内存) + 三层取数(条目/状态) + 过滤链
    alt 亲和命中（态域+容量达标）
        TR->>RD: L2 affinity_hit（续期+预占）
        TR-->>C: entry_id + data_json + lease_id + affinity=HIT
    else 亲和 MISS / 无亲和
        TR->>TR: 策略选择（四策略之一，脚本选择器可返回任意条目）
        TR->>RD: L1 绑定 + 并发预占（lease ZADD）
        TR-->>C: entry_id + data_json + lease_id + affinity=NEW|NONE
    end
    Note over C,TR: 消费方持 lease_id 调真实上游 → report 回填（5.2）
```

### 5.2 report 三态（精简版）

```mermaid
sequenceDiagram
    autonumber
    participant C as 消费方
    participant TR as token-route
    participant RD as Redis

    C->>TR: POST /v1/report {entry_id, lease_id, result, rate_units}
    TR->>RD: Lua L3：释放租约 + 速率记账（三态全记）+ 三态分支
    alt SUCCESS
        RD->>RD: 连败清零 + 窗计 ok
    else RETRYABLE_FAIL
        RD->>RD: 连败+1（≥阈值即判 FROZEN·退避）+ 窗计 fail
    else DISABLE_FAIL
        RD->>RD: 立即 FROZEN（收到即执行）
    end
    TR-->>C: {accepted, rejected[]} / 10700 部分成功
```

### 5.3 条目数据生效链（config + FEED 双真源）

```mermaid
sequenceDiagram
    autonumber
    participant OPS as 运维/开发
    participant SUP as 上游供给系统
    participant TR as token-route
    participant RD as Redis

    Note over OPS,TR: 表壳变更（策略/亲和/脚本）= 改 config + 滚动重启（启动编译 fail-fast）
    OPS->>TR: 重启加载 tr.tables → 表注册表进内存
    Note over SUP,RD: 条目数据变更 = 上游改数据 + ping 或等惰性周期
    SUP->>TR: POST /v1/refresh/{tid}（ping）
    TR->>SUP: GET refresh_url（全量）
    SUP-->>TR: {entries:[...]}
    TR->>RD: Lua L5 按 name 全量对比 upsert / 移除（缺失条目亲和脱离）
    Note over TR,RD: 无 ver——决议读 Redis 现值，变更即下一请求生效
```
